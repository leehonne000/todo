## 2026-10-23（第一天）：产品定调 → 工程落地 → 数据库就位

### 一、产品设计修订与定调（决策记录）

1. **产品哲学定调**：系统管理"用户学过并手动记录的知识"，不推荐、不指派内容；**无任务实体**——"今日任务卡"措辞修正为"今日学习卡"（状态 = 当天有无学习 session）。此哲学写入产品文档并贯穿数据设计。
2. **科目编辑增加「类型」二选一**：note / 错题（必选，默认 note），随条目落库，用于分类筛选与统计（§4.3）。
3. **Review 流程简化**：取消「模糊 / 已掌握」自判环节，完成沉浸式复习直接回主界面；复习完成自动推进一轮，六轮走完出队，无重启机制（§6）。
4. **引入 MinIO 对象存储**：图片等二进制进 MinIO 私有桶（预签名 GET 读取），文字仍存 MySQL；部署升级四容器 compose（§10）。
5. **登录体系定稿**：邮箱 + 密码为主（注册邮箱验证码激活、找回密码走邮箱），手机号预留、v1 不做短信（§1.2）。
6. **主界面新增标签查询入口**：右上角查询**图标**（非搜索框），按标签查历史记录，结果按 note / 错题分两类展示（§3.1）。
7. **图片上限 6 → 10 张/条**，文字内容**可空**（允许纯图片记录，手机端拍照优先）；总结页子条目显示类型小徽标；**条数无上限**（一条子条目 = 一条记录）。
8. **提交规则修订**：产出一律不自动 commit/push，先交用户检查，用户确认后才做 git 操作。

### 三、数据库设计与落地（docs/数据库设计.md + schema.sql）

- **10 张表**：`t_user` / `t_subject` / `t_study_session` / `t_entry`（核心）/ `t_tag` / `t_entry_tag` / `t_entry_image` / `t_check_in` / `t_exam_milestone`（全局）/ `t_verify_code`。
- 核心设计：**复习状态内嵌 `t_entry`**（round / next_due_at / review_status），不预生成计划；明确**不建**任务表、复习计划表、统计快照、复习流水。
- 图片走 MinIO（`t_entry_image` 只存 object_key 等元数据）；标签为独立词表（多对多 + 关联表）。
- 每字段绑定业务解释（对应产品文档章节），文档经多轮评审修订。
- **建表脚本** `server/src/main/resources/schema.sql`：全字段中文 COMMENT、外键/业务索引齐全、文末附注释掉的考研节点示例数据。
