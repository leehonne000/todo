## 1. 通用约定

### 1.1 基础

| 项 | 约定 |
|---|---|
| Base URL | 本地开发 `http://localhost:8080`；正式 `https://<域名>/api` |
| 数据格式 | 请求/响应均为 JSON（UTF-8）；文件上传为 multipart/form-data |
| 字段命名 | camelCase |
| 时间格式 | 时刻：`2026-10-24T18:30:00`（Asia/Shanghai）；日期：`2026-10-24` |

> **「天」= 学习日**（2026-10-25 增补）：`04:00`–次日 `04:00` 算一天，记在**起始日**（凌晨 4 点前的时刻归前一天）。适配考研作息（夜里学到很晚）。统计归桶、今日学习/签到判断、到期判断、倒计时均按此口径；时间戳本身仍是真实墙钟时刻。

### 1.2 统一响应

所有接口响应体同构：

```json
{ "code": 0, "message": "ok", "data": { } }
```

`code=0` 成功；非 0 为业务错误码（`message` 为人话原因）。**业务失败时 HTTP 状态码仍为 200**，前端以 `code` 判断成败。

### 1.3 错误码表

| code | 含义 | 典型场景 |
|---|---|---|
| 0 | 成功 | — |
| 1001 | 参数/校验失败 | 邮箱格式错、验证码无效或过期、文字与图片全空 |
| 1002 | 请求方法不支持 | GET 访问 POST 接口 |
| 2001 | 未登录 / 凭据错误 | 无票据访问受保护接口；邮箱或密码错误 |
| 2002 | 无权限 | 普通用户请求管理接口 |
| 3001 | 冲突 | 邮箱已注册 |
| 3002 | 不存在 | 邮箱未注册、接口不存在 |
| 3003 | 频率限制 | 60 秒内重复发验证码 |
| 5000 | 服务器内部错误 | 兜底 |

HTTP 状态码另见：400 参数校验失败（body 同构）、401 未登录（code=2001）、403 无权限（code=2002）、404 接口不存在（code=3002）、405 方法不支持（code=1002）。

### 1.4 鉴权

- 登录/注册成功返回 `token`（JWT，**7 天**有效）。
- 访问需登录接口时带请求头：`Authorization: Bearer <token>`。
- 除 §3（认证）外的接口全部需要票据；管理接口（§11）另需 **role=1**（超级管理员）。

### 1.5 业务边界（明确不做的接口）

| 不做 | 原因（产品文档） |
|---|---|
| 任务/计划类接口 | 产品**无任务实体**（§3），今日学习卡状态=当天有无 session，现算 |
| 全文搜索接口 | 右上角查询是**按标签查**（§3.1），不是搜索引擎 |
| 复习流水/自判接口 | 复习无自判、无重启（§6），完成即推进一轮 |
| 短信/手机登录 | v1 只做邮箱（§1.2），phone 字段预留 |
| 注册后修改科目组合 | 科目组合注册时定死（§1.2） |

### 1.6 分页约定

列表接口统一：query `page`（从 1 起，默认 1）+ `size`（默认 10，最大 50）；响应 `data`：

```json
{ "items": [], "total": 0, "page": 1, "size": 10 }
```

## 3. 认证（✅ 已完成 4 个）

### 3.1 发送验证码 `POST /api/auth/send-code`

业务（§1.2）：注册激活 / 找回密码前发 6 位验证码到邮箱。

请求体：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| email | string | ✓ | 收码邮箱 |
| purpose | int | ✓ | 1=注册激活 2=找回密码（防串用） |

规则：同邮箱同用途 **60 秒限频**（3003）；purpose=1 仅未注册邮箱（已注册 3001）；purpose=2 仅已注册邮箱（未注册 3002）。

响应：`data=null`，`code=0` 表示已发出（真实发信）。

```json
{ "code": 0, "message": "ok", "data": null }
```

### 3.2 注册 `POST /api/auth/register`

业务（§1.2）：注册时定两件事——考研届数 + 科目组合；激活码校验通过即激活。

请求体：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| email | string | ✓ | 登录邮箱 |
| password | string | ✓ | 6~32 位 |
| examYear | int | ✓ | 考研届数（如 2027） |
| code | string | ✓ | 邮箱里的 6 位验证码（purpose=1） |
| subjects | string[] | ✓ | 科目 2~5 门（如 ["政治","英语一","数学三","408"]） |

规则：验证码 10 分钟有效、一次性消费（用过即废，1001）；邮箱已注册 3001。

响应 `data`（注册完即登录态）：

```json
{ "code": 0, "message": "ok",
  "data": { "token": "eyJhbGciOi...", "userId": 6, "email": "xx@qq.com" } }
```

### 3.3 登录 `POST /api/auth/login`

业务（§1.2）：邮箱+密码登录；**未激活禁登录**。

请求体：`{ "email": string, "password": string }`

规则：账号或密码错统一报 2001（不泄露哪个错）。响应 `data` 同注册。

### 3.4 找回密码 `POST /api/auth/reset-password`

业务（§1.2）：忘密码 → 邮箱验证码换新密码。

请求体：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| email | string | ✓ | 注册邮箱 |
| code | string | ✓ | purpose=2 的验证码（注册码不能改密） |
| newPassword | string | ✓ | 6~32 位 |

规则：邮箱未注册 3002；改密后旧密码立即失效。响应 `data=null`。

### 3.5 用户资料（2026-10-25 增补）

产品：自定义页展示头像+昵称。**注册流程不变**，注册成功时后端自动赋默认值——昵称 = 邮箱 `@` 前缀，头像 = 系统默认头像。数据库 `t_user` 新增 `nickname VARCHAR(20)`、`avatar_object_key VARCHAR(255)`。

#### 3.5.1 获取资料 `GET /api/profile`

响应 `data`：

```json
{ "code": 0, "message": "ok",
  "data": { "userId": 6, "email": "demo@kaoyan.com",
            "nickname": "demo", "avatarUrl": "/avatar-default.png",
            "examYear": 2027 } }
```

avatarUrl 为可直接渲染的地址（对象存储时为预签名 URL）。

#### 3.5.2 修改资料 `PUT /api/profile`

请求体（整体可选，至少传一项）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| nickname | string | 否 | 1~20 字符（1001 越界） |
| avatarObjectKey | string | 否 | 先调 §5.5 上传拿 objectKey |

响应 `data`：`{ "userId": 6, "nickname": "…", "avatarUrl": "…" }`。

## 5. Learn 流程（✅ 已完成 5 个）

调用时序：`GET /api/subjects`（选科目）→ `POST /api/sessions`（开始计时）→ `POST /api/sessions/{id}/finish`（长按结束）→ `POST /api/uploads/images`（编辑时传图，可多次）→ `POST /api/sessions/{id}/entries`（Done 落库）。

### 5.1 科目列表 `GET /api/subjects`

业务（§4.1）：Learn 入口选科目四选一（注册时定的组合）。

响应 `data`：

```json
{ "code": 0, "message": "ok",
  "data": [ { "id": 1, "name": "政治", "sortOrder": 0 },
            { "id": 2, "name": "英语一", "sortOrder": 1 } ] }
```

### 5.2 开始计时 `POST /api/sessions`

业务（§4.1/§4.2）：选完科目进入横屏计时那一刻建行（保证中断不丢）。

请求体：`{ "subjectId": 2 }`（一次 session 只学一门）

响应 `data`：

```json
{ "code": 0, "message": "ok", "data": { "id": 11, "startedAt": "2026-10-24T19:00:00" } }
```

### 5.3 结束计时 `POST /api/sessions/{id}/finish`

业务（§4.2）：长按结束按钮——写入净学习秒数（**排除暂停时长**，暂停是前端本地逻辑）。

请求体：`{ "durationSeconds": 3600 }`

响应 `data=null`。异常中断（没调 finish）也不影响统计（duration 保持 0/已写值）。

### 5.4 Done 批量落库 `POST /api/sessions/{id}/entries`

业务（§4.3/§6）：总结页点 Done——本次全部子条目同事务落库；**每条自动进艾宾浩斯队列**（round=0，next_due_at=记录日+1 天）。

请求体：

```json
{
  "entries": [
    { "type": 1, "content": "政治新增考点……", "tagNames": ["马原"], "imageObjectKeys": ["user_6/tmp/abc.webp"] },
    { "type": 2, "content": "", "tagNames": ["极限"], "imageObjectKeys": ["user_6/tmp/def.webp"] }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| entries[].type | int | ✓ | 1=note 2=错题（总结页入口按钮定死） |
| entries[].content | string | 否 | 文字可空（纯图片记录），**文字与图片至少一**（1001） |
| entries[].tagNames | string[] | 否 | 标签名（同名复用，自动建词表） |
| entries[].imageObjectKeys | string[] | 否 | 上传接口返回的 objectKey；每条**最多 10 张**（1001） |

响应 `data`：创建的记录 id 列表。科目继承自 session（前端不用传）。

### 5.5 图片上传 `POST /api/uploads/images`

业务（§4.4/§5.1）：记录编辑「＋图片」与文章封面共用。`multipart/form-data` 字段 `file`（≤10MB）。

服务端压缩转 webp 后入 MinIO。响应 `data`：

```json
{ "code": 0, "message": "ok",
  "data": { "objectKey": "user_6/tmp/abc.webp", "contentType": "image/webp", "sizeBytes": 182043,
            "previewUrl": "https://...（预签名，短时效）" } }
```

> objectKey 为临时键，Done 时随条目提交后由后端归档到条目名下；前端拿 `previewUrl` 直接渲染缩略图。

**实现说明（2026-10-26）**：

- **存储 = MinIO 私有桶 `exam-timeline`**（`MinioStorageService`，Java SDK `io.minio:minio`）：上传写临时键 `user_{uid}/tmp/{uuid}.{ext}`，Done 归档 `user_{uid}/entry_{eid}/{文件名}`（MinIO 无 rename，服务端 copy+删源）；原始文件名走对象 user metadata（x-amz-meta-original-name）。
- **previewUrl = SDK 预签名 GET**（短时效，默认 12h）：绝对 URL 直达 MinIO，前端原样放 `img.src`；不走 JWT（`<img>` 带不了请求头）。开发机注意 `MINIO_ENDPOINT` 要填浏览器能访问到的地址。
- **压缩转 webp**（gotson webp-imageio：无透明有损 0.82 / 有透明无损）；编码器异常时自动回退 jpg/png，`contentType` 按实际格式返回。
- **镜像分发现状（2026-10-26 已解决）**：MinIO 官方已停发免费容器镜像（Docker Hub/quay/ECR/ghcr/dl.min.io 全灭），第三方 Minimus 2026-10-22 关停。**解决方案：从官方源码（经 goproxy.cn）自建纯净镜像**（scratch + minio 二进制 + CA 证书，无其他任何软件），已本地打标 `minio/minio:latest`，构建配方见 `temp/minio-image/build.sh`（可复现，其他项目通用）。Learn 图片链路已对该镜像端到端回归通过（上传 webp 压缩、预签名取图、Done 归档 tmp→entry）。

## 6. Review 复习队列（✅ 已完成 2 个）

### 6.1 今日到期列表 `GET /api/reviews/due`

业务（§3/§6）：**艾宾浩斯队列唯一消费入口**——Review 卡点击进沉浸式复习。

响应 `data`：到期记录数组（跨科目堆叠；前端可按科目组织展示）：

```json
{ "code": 0, "message": "ok",
  "data": [ { "id": 3, "subjectName": "数学三", "type": 2, "content": "……",
              "tags": ["极限"], "images": [ { "objectKey": "…", "previewUrl": "…" } ],
              "round": 1, "createdAt": "2026-10-23T20:11:00" } ] }
```

查询口径：`review_status=0 AND next_due_at <= 今天`（数据库设计 §5-1）。

### 6.2 复习完成 `POST /api/reviews/{entryId}/complete`

业务（§6）：**无自判**——完成该项沉浸式复习即调用。请求体无。

后端动作：`round+1`，按节奏 `1/2/4/7/15/22` 天（相对记录日）顺延 `next_due_at`；**round=6 → review_status=1、next_due_at=null 出队**（只留自由库）。响应 `data`：

```json
{ "code": 0, "message": "ok", "data": { "round": 2, "nextDueAt": "2026-10-28" } }
```

## 8. 进度模块（未开始）

### 8.1 统计 `GET /api/progress`

业务（§5.3）：以日期为轴的每日统计。参数 `from`、`to`（日期，默认本月 1 日至今）。

响应 `data.days[]`（口径见数据库设计 §4，全部**精确**）：

```json
{ "code": 0, "message": "ok",
  "data": { "days": [
    { "date": "2026-10-24",
      "totalSeconds": 7200,
      "bySubject": [ { "subjectName": "数学三", "seconds": 3600 },
                      { "subjectName": "408", "seconds": 3600 } ],
      "noteCount": 3, "wrongCount": 1 } ],
    "checkInDates": ["2026-10-19", "2026-10-20", "2026-10-22"] } }
```

- totalSeconds/bySubject：session 净学习秒数按 `started_at` 的**学习日** + 科目汇总
- noteCount/wrongCount：entry 按 `created_at` 的**学习日** + type 计数
- checkInDates（2026-10-25 增补）：区间内签到日期列表，供统计页「签到日历 / 连续签到」渲染；无签到为 `[]`

## 9. 信息模块（未开始）

### 9.1 固定信息区 `GET /api/info/overview`

业务（§5.1）：倒计时 + 考研硬节点时间线（全站唯一的"日历"能力）。

响应 `data`：

```json
{ "code": 0, "message": "ok",
  "data": { "examYear": 2027, "daysLeft": 56,
            "milestones": [ { "name": "预报名", "dateFrom": "2026-09-24", "dateTo": "2026-09-27", "sortOrder": 1 },
                            { "name": "初试", "dateFrom": "2026-12-19", "dateTo": "2026-12-20", "sortOrder": 5 } ] } }
```

`daysLeft` = 用户届数下"初试"的 date_from − 今天。

### 9.2 文章列表 `GET /api/articles`

业务（§5.1）：博客区列表（**只含已发布**，倒序）。分页参数同 §1.6。

响应 `data.items[]`：`{ id, title, coverUrl, publishedAt }`（coverUrl 为预签名 URL，无封面为 null）。

### 9.3 文章详情 `GET /api/articles/{id}`

业务（§5.1）：点击进详情阅读。响应 `data`：`{ id, title, content, coverUrl, publishedAt }`。规则：**草稿对普通用户不可见**（3002）。

## 11. 管理后台（未开始，需 role=1）

> 权限（§11.2）：以下接口仅超级管理员可调用；普通用户调用报 **2002**。管理员同时拥有全部普通用户权限（§3–§9 都可正常调）。

### 11.1 文章列表 `GET /api/admin/articles`

业务（§11）：管理文章（**含草稿**）。参数 `status`（0/1，可选）、分页。响应 `data.items[]`：`{ id, title, status, publishedAt, updatedAt }`。

### 11.2 新建文章 `POST /api/admin/articles`

业务（§11）：写作存**草稿**。请求体：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| title | string | ✓ | 标题（≤120 字） |
| content | string | ✓ | 正文（v1 纯文本/Markdown 原文） |
| coverObjectKey | string | 否 | 封面（先调 §5.5 上传） |

响应 `data`：`{ "id": 1 }`。

### 11.3 编辑文章 `PUT /api/admin/articles/{id}`

业务（§11）：改标题/正文/封面（整体替换式）。请求体同 11.2。响应 `data=null`。

### 11.4 发布 `POST /api/admin/articles/{id}/publish`

业务（§5.1/§11）：草稿 → 已发布（对全员可见）。首次发布写 `publishedAt`（列表倒序依据）。响应 `data=null`。

### 11.5 下线 `POST /api/admin/articles/{id}/unpublish`

业务（§11）：已发布 → 草稿（软控制，保留文章行，可再次发布）。响应 `data=null`。

### 11.6 删除文章 `DELETE /api/admin/articles/{id}`

业务（§11）：物理删除（封面对象一并清理）。响应 `data=null`。

### 11.7 查用户 `GET /api/admin/users`

业务（§11）：按 id/邮箱定位用户（提拔入口）。参数 `keyword`、分页。

响应 `data.items[]`：`{ id, email, role, examYear, createdAt }`（**不返回密码哈希**）。

### 11.8 提拔/取消管理员 `POST /api/admin/users/{id}/role`

业务（§11.2）："把指定 id 的 user 变为超级管理员" / 取消。请求体：`{ "role": 1 }`（1=提拔，0=取消）。

规则：注册永远只产普通用户（role=0），管理员只能由此接口产生；第一个管理员由部署者在库中指定（种子）。响应 `data`：`{ "id": 6, "role": 1 }`。

## 12. 典型时序：一次完整 Learn 闭环

```
1  GET  /api/home                        → Review 卡显示 0，今天还没学
2  GET  /api/subjects                    → 选「数学三」(id=2)
3  POST /api/sessions      {subjectId:2} → sessionId=11
        （横屏计时中……暂停/继续是前端本地行为）
4  POST /api/sessions/11/finish  {durationSeconds:3600}
5  POST /api/uploads/images   (file)     → objectKey A        （可多次，添加note/错题时）
6  POST /api/sessions/11/entries
      { entries: [ {type:1, content:"…", tagNames:["极限"], imageObjectKeys:[A]} ] }
        → 记录入队：round=0, next_due_at=明天
7  POST /api/check-ins                   → 签到
8  （次日）GET /api/reviews/due           → 昨天那条到期
9  POST /api/reviews/3/complete          → round=1, next_due_at=+2 天
10 GET  /api/progress?from=&to=          → 各科耗时/条数统计
```
