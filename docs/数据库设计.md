# 考研时间线系统 · 数据库设计

> 数据层唯一权威文档；产品语义以 `docs/考研时间线系统-产品设计文档.md` 为准（下称"产品文档"）。
> 建表 SQL 待本文档评审通过后另行产出。
> 状态：**待评审**（2026-10-23）。

## 0. 设计原则（先读）

1. **内容全部由用户喂入**：系统是"学习成果管理器"，不生产、不推荐、不指派任何内容。数据库只为用户手动记的 note/错题做**组织、排期、统计**。
2. **复习状态内嵌记录**：不预生成 6 行复习计划。一条记录一行，用 `round / next_due_at / review_status` 三个字段表达艾宾浩斯状态机（产品文档 §6）。
3. **`user_id` 贯穿每张业务表**：多用户隔离，按用户查询不用绕 join。全局表只有 `t_exam_milestone` 一张。
4. **文字进 MySQL，二进制进 MinIO**：文字要检索、筛选、统计；图片本体存 MinIO 私有桶，库里只存元数据（产品文档 §10）。
5. **时间口径**：时刻用 `DATETIME`（Asia/Shanghai）；按"天"走的业务（复习到期、签到）用 `DATE`。
6. **明确不建的表**见 §3——任务表、复习计划表、统计快照表、复习流水表都不存在。

**通用约定**：InnoDB，`utf8mb4`；主键 `id BIGINT UNSIGNED AUTO_INCREMENT`；写入类时间字段 `created_at`，可编辑的表加 `updated_at`。

## 1. 表总览与 ER

## 2. 表结构明细

### 2.1 t_user —— 用户

**业务绑定**：注册制多用户（§1.2）；**登录方式 = 邮箱 + 密码**（2026-10-23 定，邮箱为主）；注册时确定考研届数；登录鉴权；信息模块倒计时（§5.1）。

| 字段 | 类型 | 约束 | 业务解释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 主键，全库唯一标识一个用户 |
| `email` | VARCHAR(64) | NOT NULL, UNIQUE | **登录标识**：注册填邮箱并收激活验证码；登录、找回密码都认它。唯一索引天然防重复注册（§1.2 注册制） |
| `password_hash` | VARCHAR(100) | NOT NULL | 密码哈希（BCrypt）；"邮箱 + **密码登录**"的凭据，不存明文 |
| `email_verified` | TINYINT | NOT NULL DEFAULT 0 | 邮箱激活标志：注册验证码校验成功置 1；未激活不允许登录（防乱填邮箱注册） |
| `phone` | VARCHAR(20) | NULL, UNIQUE | 手机号**预留字段**（v1 不用）：短信签名资质是个人开发者的门槛，v1 不做短信验证；留着将来加手机绑定/登录不用迁移表 |
| `exam_year` | SMALLINT | NOT NULL | 考研届数（如 2027）：注册时确定的两件事之一；信息模块"距离 XXXX 年考研还有 XXX 天"用它去 `t_exam_milestone` 取初试日期算倒计时（§1.2/§5.1） |
| `created_at` | DATETIME | NOT NULL | 注册时间 |
| `updated_at` | DATETIME | NOT NULL | 资料变更时间 |

> 无昵称/显示名字段：产品没有社交场景（§1.3 明确不做），界面上不需要展示用户名；将来要再加 `display_name` 可空字段即可。

### 2.2 t_subject —— 科目组合

**业务绑定**：注册时确定的科目组合（四门，如 政治/英语一/数学三/408）（§1.2）；科目编辑界面"折叠式科目选项卡"四选一的选项来源（§4.3）；复习模块自由库按科目分类（§5.2）；进度模块按科目统计（§5.3）。

| 字段 | 类型 | 约束 | 业务解释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 主键 |
| `user_id` | BIGINT UNSIGNED | NOT NULL, FK→t_user | 归属用户；每用户 2~5 门，注册时录入 |
| `name` | VARCHAR(64) | NOT NULL | 科目名，用户自定义文本（不限届数、不限科目，符合"不局限于任何一届考生"§1.2） |
| `sort_order` | TINYINT | NOT NULL | 展示顺序：科目选项卡的四选一排列、进度模块统计表头顺序 |
| `created_at` | DATETIME | NOT NULL | 创建时间 |

唯一键 `(user_id, name)`：同一用户科目不重名。
删除科目不级联删记录——`t_entry.subject_id` 用 RESTRICT，防止误删历史记录。

### 2.3 t_study_session —— 学习 session

**业务绑定**：Learn 流程横屏计时的产物（§4.1）；"数据引擎闭环"里"学习时长 → 进度模块"这一路（§8）；今日学习卡"今天学没学"的打勾状态来源（§3）。

**生命周期**（保证计时中断不丢数据）：点开始计时即建行写 `started_at` → 长按结束补 `ended_at` + `duration_seconds` → 学习总结页点「Done」时同事务写入本次的 `t_entry`（§4.2）。

| 字段 | 类型 | 约束 | 业务解释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 主键 |
| `user_id` | BIGINT UNSIGNED | NOT NULL, FK→t_user | 归属用户 |
| `started_at` | DATETIME | NOT NULL | 计时开始时刻：横屏界面进入计时的那一刻 |
| `ended_at` | DATETIME | NULL | 长按结束时刻；可空——异常中断（杀进程）时为空，但不影响统计 |
| `duration_seconds` | INT | NOT NULL DEFAULT 0 | **净学习秒数** = 横屏界面上方小字计时器的最终读数（累计计时，**排除暂停时长**）（§4.1）；进度模块一切时长统计的原始值 |
| `created_at` | DATETIME | NOT NULL | 记录创建时间 |

索引 `(user_id, started_at)`：进度模块按日期范围聚合的主力索引（§5.3）。

### 2.4 t_entry —— 记录项（★ 核心表）

**业务绑定**：学习总结页的**子条目**（§4.2）+ 科目编辑界面填写的内容（§4.3）；复习模块自由库的本体（§5.2）；艾宾浩斯复习队列（§6）；进度模块笔记数/错题数（§5.3）。产品里最重要的数据都在这张表。

| 字段 | 类型 | 约束 | 业务解释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 主键 |
| `session_id` | BIGINT UNSIGNED | NOT NULL, FK→t_study_session | 来自哪次 Learn：把"学了多久"（session）和"学了什么"（entry）钉在一起，是 §8 数据闭环的连接点 |
| `user_id` | BIGINT UNSIGNED | NOT NULL, FK→t_user | 归属用户（冗余字段，自由库/队列查询免 join） |
| `subject_id` | BIGINT UNSIGNED | NOT NULL, FK→t_subject | 科目编辑四选一的落库值（§4.3）；自由库按科目分类（§5.2）、进度按科目统计（§5.3）的维度 |
| `type` | TINYINT | NOT NULL | 记录类型：**1=note，2=错题**——科目编辑界面"note/错题"二选一选项卡的落库值（§4.3）；自由库筛选、进度模块"笔记数/错题数"分开统计的依据 |
| `content` | TEXT | NULL | **文字内容**：用户手动输入的知识本体（§4.3）。**可空**——允许"纯图片"记录（手机端写字麻烦、拍照为主，2026-10-23）；应用层校验"文字与图片至少有一" |
| `round` | TINYINT | NOT NULL DEFAULT 0 | 艾宾浩斯**已完成轮数**（0~6）：入库为 0，每完成一次复习 +1（§6.1） |
| `next_due_at` | DATE | NULL | **下一轮到期日**：入库 = 记录日 + 1 天；此后按节奏取记录日起第 2/4/7/15/22 天（§6.1）。主界面 Review 卡"今日应复习"就查 `next_due_at <= 今天` |
| `review_status` | TINYINT | NOT NULL DEFAULT 0 | 复习状态：**0=队列中，1=已出队**。round 走满 6 轮置 1 并清空 `next_due_at`；出队后只留在自由库（§6.1） |
| `created_at` | DATETIME | NOT NULL | 入库时间（总结页点「Done」的时刻）；同时是艾宾浩斯六轮排期的基准日（§6.1） |
| `updated_at` | DATETIME | NOT NULL | 最后编辑时间：自由库允许修改已记录内容（§5.2） |

索引：
- `(user_id, review_status, next_due_at)` —— Review 卡到期查询（§3/§6）
- `(user_id, subject_id, type)` —— 自由库筛选与进度统计（§5.2/§5.3）
- `(user_id, session_id)` —— 查某次学习的全部记录

删除策略：物理删除，级联删 `t_entry_tag` / `t_entry_image`——复习状态随记录走，删了就整条消失（自由库不留空壳）。

### 2.5 t_tag / t_entry_tag —— 标签及关联

**业务绑定**：科目编辑界面"自定义标签"（点「＋标签」回车生成琥珀 chip，§4.3）；自由库按标签筛选（§5.2）；**主界面右上角标签查询**（产品文档 §3.1，结果按 note/错题分两类）。

**t_tag**

| 字段 | 类型 | 约束 | 业务解释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 主键 |
| `user_id` | BIGINT UNSIGNED | NOT NULL, FK→t_user | 归属用户：标签是用户私有词表 |
| `name` | VARCHAR(32) | NOT NULL | 标签文本（chip 上的字） |
| `created_at` | DATETIME | NOT NULL | 首次创建时间 |

唯一键 `(user_id, name)`：同名标签复用，不重复建。

**t_entry_tag**

| 字段 | 类型 | 约束 | 业务解释 |
|---|---|---|---|
| `entry_id` | BIGINT UNSIGNED | PK 组成, FK→t_entry | 记录项 |
| `tag_id` | BIGINT UNSIGNED | PK 组成, FK→t_tag | 标签 |
| `created_at` | DATETIME | NOT NULL | 关联时间 |

> 为什么独立两张表：标签要参与**筛选和统计**，逗号拼字符串存 TEXT 无法走索引、无法按标签聚合。

### 2.7 t_entry_image —— 图片元数据

**业务绑定**：科目编辑界面"图片插入"（「＋」虚线方块，手机相册/拍照/电脑上传，缩略图 72px，**上限 10 张**，§4.3）。**图片本体在 MinIO**（私有桶 `exam-timeline`，§10），本表只存指路牌。图片是手机端的主要内容载体（2026-10-23 定：拍照优先于打字）。

| 字段 | 类型 | 约束 | 业务解释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 主键 |
| `entry_id` | BIGINT UNSIGNED | NOT NULL, FK→t_entry | 所属记录项；一条记录最多 **10** 张（应用层校验，§4.3） |
| `user_id` | BIGINT UNSIGNED | NOT NULL, FK→t_user | 归属用户（MinIO object key 里也含 user，双保险） |
| `object_key` | VARCHAR(255) | NOT NULL, UNIQUE | **MinIO 对象键**：`user_{userId}/entry_{entryId}/{uuid}.webp`。上传链路：前端 → Spring Boot 压缩（§10）→ 写 MinIO → 本表落 object_key；读取：按它签发预签名 GET URL |
| `original_name` | VARCHAR(255) | NULL | 上传时的原始文件名（自由库展示/下载用，纯观赏性字段） |
| `content_type` | VARCHAR(40) | NOT NULL | MIME 类型（如 `image/webp`）：签发预签名 URL 时回填 Content-Type，浏览器才能正确渲染 |
| `size_bytes` | INT | NOT NULL | 压缩后对象大小：容量统计、排错、上传校验 |
| `sort_order` | TINYINT | NOT NULL DEFAULT 0 | 缩略图排列顺序（0~9），对应编辑界面缩略图的先后 |
| `created_at` | DATETIME | NOT NULL | 上传时间 |

> 容量参考：服务端压缩（长边 ~1600px、webp）后单张约 100–300KB，一条记录 10 张约 1~3MB；MinIO 数据卷跟 MySQL 备份一起走日常备份即可，无单独容量规划需求。

### 2.7 t_check_in —— 签到

**业务绑定**：主界面"签到（每日打卡）"（§3）。签到管"来了没有"，今日学习卡管"学了没有"，两者是主界面的一对状态。

| 字段 | 类型 | 约束 | 业务解释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 主键 |
| `user_id` | BIGINT UNSIGNED | NOT NULL, FK→t_user | 归属用户 |
| `check_in_date` | DATE | NOT NULL | 打卡自然日（按天，不是按时刻） |
| `created_at` | DATETIME | NOT NULL | 打卡时刻 |

唯一键 `(user_id, check_in_date)`：**天然防重复打卡**——重复点签到只会撞唯一键，不需要额外判断逻辑。

### 2.8 t_exam_milestone —— 考研硬节点（全局表）

**业务绑定**：信息模块"考研硬节点时间线"（§5.1）——预报名/正式报名/网上确认/准考证下载/初试/出分/国家线/复试调剂；产品文档明确"数据化，不写死；每年教育部公布后更新数据"。**全库唯一不带 user_id 的表**。

| 字段 | 类型 | 约束 | 业务解释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 主键 |
| `exam_year` | SMALLINT | NOT NULL | 届数：与 `t_user.exam_year` 对齐，取"我这一届"的节点集合 |
| `name` | VARCHAR(32) | NOT NULL | 节点名（初试、国家线…），即 §5.1 表格第一列 |
| `date_from` | DATE | NOT NULL | 节点起始日；"距离 XXXX 年考研还有 XXX 天"= 用户届数下 `name='初试'` 的 `date_from` |
| `date_to` | DATE | NULL | 节点结束日（复试/调剂 3–4 月跨月区间用；单日节点留空） |
| `sort_order` | TINYINT | NOT NULL | 时间线展示顺序 |
| `updated_at` | DATETIME | NOT NULL | 数据维护时间（每年教育部公布后更新） |

### 2.9 t_verify_code —— 邮箱验证码

**业务绑定**：登录体系的两个流程——**注册邮箱激活** + **找回密码**（§1.2）。发码走 SMTP 到用户邮箱；v1 验证码直接落 MySQL（量级小，**不引 Redis**）。

| 字段 | 类型 | 约束 | 业务解释 |
|---|---|---|---|
| `id` | BIGINT UNSIGNED | PK | 主键 |
| `email` | VARCHAR(64) | NOT NULL | 收码邮箱（即登录标识）；不设外键——找回密码时用户还没登录，验证码允许指向任意邮箱 |
| `code` | VARCHAR(8) | NOT NULL | 6 位数字验证码，发到邮箱的那串数字 |
| `purpose` | TINYINT | NOT NULL | 用途：**1=注册激活，2=找回密码**。一张表管两个流程，带用途防串用（注册的码不能拿来改密码） |
| `expires_at` | DATETIME | NOT NULL | 过期时刻（10 分钟）；过期作废，重发后以最新一条有效 |
| `used_at` | DATETIME | NULL | 消费时刻；NULL=未用。校验通过时置值——防同一验证码重复使用 |
| `created_at` | DATETIME | NOT NULL | 发码时间；同时用于**限频**（同邮箱 60 秒内不重复发码，防轰炸） |

索引 `(email, purpose, expires_at)`：校验时"取最新未过期未使用的码"。

## 3. 明确不建的表（防止将来想歪）

| 不建 | 为什么 |
|---|---|
| **任务表** | 产品没有"任务"实体（2026-10-23 定调）：内容全部用户学完手动记录，系统不布置任务。"今日学习卡"打勾状态 = 当天是否存在 `t_study_session`，现查即可 |
| **复习计划表**（每记录 6 行） | 复习状态内嵌 `t_entry`（round/next_due_at/review_status），"模糊重启"机制已取消（§6 修订），状态机极简，无需计划行 |
| **统计快照表** | 进度模块全部现算（单用户日均几条记录，量级用不着物化） |
| **复习流水表** | v1 不留每次复习痕迹；将来若做"复习热力图"再加 `t_review_log`，不影响现有结构 |

## 4. 统计口径（进度模块 §5.3）

| 指标 | 口径 | 精确性 |
|---|---|---|
| 每日总学习时长 | `SUM(duration_seconds)` 按 `DATE(started_at)` 分组 | 精确 |
| 每日笔记数/错题数 | `t_entry` 按 `DATE(created_at)` + `type` 计数 | 精确 |
| **每日各科目耗时** | 该日 session 时长按该 session 涉及的科目**均分** | **估算**（待拍板，见 §6） |

> 说明：一次 Learn 可记多门科目（§4.2"可添加多门科目"），但计时器只有 session 总时长，科目编辑界面也没有分科计时。v1 口径定为均分（一次 2 小时 session 记了数学+408 → 各 1 小时）。若将来要精确，可在 `t_entry` 加 `duration_seconds` 字段并让用户在总结页分配，无需重构。

## 5. 核心查询清单（业务场景 → 查询路径）

1. **Review 卡今日到期数/列表**（§3/§6）：`WHERE user_id=? AND review_status=0 AND next_due_at<=CURDATE()` → 走 `(user_id, review_status, next_due_at)`
2. **复习完成推进一轮**（§6）：`UPDATE t_entry SET round=round+1, next_due_at=<记录日+对应间隔>, review_status=... WHERE id=?`；round=6 时置 `review_status=1, next_due_at=NULL`
3. **自由库浏览/筛选**（§5.2）：`WHERE user_id=? [AND subject_id=?] [AND type=?] [AND tag_id=?] ORDER BY created_at DESC`
4. **进度模块日/区间统计**（§5.3）：session 按 `started_at` 范围聚合 + entry 按 `created_at` 范围聚合
5. **倒计时**（§5.1）：`t_user.exam_year` → `t_exam_milestone WHERE exam_year=? AND name='初试'` → 与今天求差
