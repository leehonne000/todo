## 1. 产品定位

**面向多用户的「考研时间线规划辅助系统」**——不是普通 todo 工具。

设计哲学借鉴《不背单词》App：**系统替用户安排学习，而不是让用户记录待办**。
用户只负责"学"和"记"，系统负责"什么时候该复习什么"。

### 1.1 设计哲学（不背单词借鉴点）

| 不背单词的做法 | 本产品的对应 |
|---|---|
| 打开 App 就是今日学习任务 | 打开就是主界面：签到 + 今日学习 + 今日应复习 |
| 系统按记忆曲线安排单词复习 | 系统按艾宾浩斯曲线安排 note/错题复习 |
| Learn / Review 卡片直达 | Learn / Review 卡片直达，全屏沉浸式流程 |
| 壁纸 + 毛玻璃 + 琥珀橙数字 | 同款视觉语言（见 §7） |
| 底部三图标导航 | 底部三图标 = 三大模块入口（hub-and-spoke） |

### 1.2 目标用户与多用户

- **多用户系统**，账号注册制。
- **登录方式（2026-10-23 定）**：**邮箱 + 密码**为主——注册填邮箱并收激活验证码，登录用邮箱+密码，找回密码走邮箱验证码；手机号为预留字段，v1 不做短信验证。
- **注册时确定两件事：考研届数 + 科目组合**（绝大多数为四门，如 政治 / 英语一 / 数学三 / 计算机学科专业基础综合(408)）。之后所有模块按此科目组合四选一。
- 不局限于任何一届考生——届数、科目均为用户自定义。

### 1.3 明确不做（v1）

- 商业化、组队、社交（不背学堂类功能）——留空位不实现。
- OCR（图片不识别文字，v1 只存图）。
- 离线支持（待定，见 §10）。

## 2. 导航模型：中心辐射（hub-and-spoke）

**这是被多次纠正后定稿的关键结构，实现时不得走样：**

- 进入应用后**默认显示主界面**（根屏），主界面**不与任何底部图标绑定**。
- 底部导航栏三个图标 = 三大模块**入口**（不是平行 tab）：
  - **左：信息模块** —— 「距离 XXXX 年考研还有 XXX 天」等信息、考研硬节点时间线，以及**超级管理员发布的博客内容**（§5.1，2026-10-24 增补）。
  - **中：复习模块** —— 对过去学过内容的**自由库**复习。
  - **右：进度模块** —— 对整体的规划与统计。
- **无论从哪个模块退出，都直接退回主界面**（不回上一个模块、不在模块间切换）。
- 主界面自己提供 Learn / Review 两个卡片入口（见 §3）。

```
              ┌─────────────┐
   信息模块 ←──┤   主 界 面   ├──→ 复习模块
              │ (常驻根屏)  │
   进度模块 ←──┤             │
              └─────────────┘
   （退出任一模块 → 直接回主界面）
```

## 3. 主界面

主界面包含三块内容 + 一个右上角入口：

Demo 参考：`temp/demo_1_main.html`（2026-10-24）。

1. **签到**（每日打卡）。
2. **今日学习卡（Learn）** —— 今天的**学习入口 + 学习状态**（今天完成过 Learn session 则打勾）。注意：系统**没有"任务"实体**——内容全部由用户学完手动记录，系统不布置任务；点击进入 Learn 沉浸式流程（§4）。
3. **今日应复习卡（Review）** —— **艾宾浩斯复习队列的唯一入口**。到期待复习的 note/错题在此汇总，点击进入全屏沉浸式复习流程（§6）。
4. **右上角查询图标**（2026-10-23 新增）：一个**图标**（放大镜），**不是搜索框**——不占主界面内容位，不破坏壁纸+卡片的视觉。点击进入**标签查询**（§3.1）。

### 3.1 标签查询（主界面右上角入口）

- 点击右上角查询图标 → 进入查询界面，按**标签**检索历史记录：从用户的标签词表（§4.4 自定义标签）中选择，支持输入过滤快速定位标签。
- **类别 tab**（2026-10-25）：全部 / note / 错题 三选一（全站「选一个」统一下划线 tab 样式），控制结果分区显隐。
- **结果按 note / 错题分两类展示**（两个分区）：每条显示内容摘要、所属科目、记录日期。
- **提示语固定三条**（2026-10-25）：输入框占位「输入标签后自动查询」、空结果「没有对应的note」「没有对应的错题」，不放其他提示。
- 点击条目进入详情（复用复习模块自由库的详情/编辑能力，§5.2）。
- **与复习模块自由库的边界**：本入口 = 按标签**跨科目**快速查；自由库 = 按科目浏览全部记录。两者查的是同一份数据（记录项）。

> 关键澄清：艾宾浩斯队列**只**通过主界面 Review 卡消费；底部中间的复习模块**不提供**队列，只是自由库（见 §5.2）。

## 4. Learn 流程（今日学习卡点入）

### 4.1 选科目（计时前第一步，2026-10-24 新增）

- 点主界面 Learn 卡 → **先进入选科目界面**：从注册时确定的科目组合中**四选一**（一门）。
- **一次 Learn session 只学一门科目**：科目在计时开始前定死，本次学习产出的全部 note / 错题都归属这门科目，之后不可更改。
- 这样「每日各科目耗时」可**精确统计**——session 与科目一一对应（§5.3/§8），用户不需要在总结页手动分配时长。
- 选定科目后进入横屏计时界面（§4.2）。

Demo 参考：`temp/demo_2_subject_select.html`（2026-10-24）。

### 4.2 计时界面（横屏沉浸式）

- **手机端锁死横屏**。
  - 注意：iOS Safari 网页不支持硬锁横屏，方案为**"请横过来"整屏引导遮罩**替代硬锁；Android/PC 按需处理。
- 横屏界面四要素（用户手绘草图定稿）：
  1. **最中间**：当前时间（时分秒，或用户自定义为时分）。
  2. 当前时间**上方**：小字号的**学习计时器**。
  3. **左下角**：**暂停按钮**（圆形蓝色）；点击暂停计时，按钮变为**正方形**（暂停态）。
  4. **右下角**：**结束按钮**，**长按**才结束本次学习的计时部分。

Demo 参考：`temp/demo_3_timer.html`（2026-10-24，横屏框 + 长按进度环）。

补充（2026-10-25）：
- **左上「圈+笔」画面自定义按钮**（计时页是久待界面，需缓解压抑感）：面板四项——呼吸光晕（默认开）/粒子飘动（默认开）/秒数跳动/背景暗度 0~80%，偏好本地记忆。位置锚定同 Done：手机贴角、宽屏随舞台左缘内移。
- 两个时间数字**同帧跳秒**（共用同一心跳驱动，起点量化到整秒，误差 ≤0.5s），避免大小字翻秒错相。

### 4.3 学习总结页（长按结束后进入）

界面极简，只有**三件套** + 已添加的子条目（多余元素全部删除，2026-10-24 修订）：

- **「添加note」** 通栏毛玻璃框按钮。
- **「添加错题」** 通栏毛玻璃框按钮。
- **右下角琥珀色「Done」** 胶囊按钮。

交互：

- 科目已在 Learn 入口选定（§4.1），总结页**不再有「＋添加科目」、不再选科目**。
- 点「添加note」或「添加错题」→ 进入**记录编辑界面**（§4.4），**类型由所点按钮定死**（note / 错题），编辑页内不再二选一。
- 编辑完成后返回总结页，该条以**子条目**形式**紧紧贴在两个添加按钮正下方**——比按钮框**小一点**、像它们的**子标签**（`margin-top: 3px`、左缩进、圆角只在下方、字号更小、右侧 `›` chevron），点击子条目可再次进入编辑。子条目携带**类型小徽标**（note 灰底 / 错题琥珀底，`›` 箭头前），一眼可辨。
- **子条目条数无上限**：同一科目下 note 和错题可并存、可加多条（例：2 条 note + 1 条错题）。**一条子条目 = 一条记录**（一个类型），各条独立进入艾宾浩斯队列（§6）。
- 点「Done」→ 本次学习 session 数据落库（见 §8 数据引擎闭环）。

Demo 参考：`temp/demo_4_summary.html`（三件套 + 子条目，2026-10-24 重做）。

## 5. 三大模块

### 5.1 信息模块（底部左）

模块内容分两部分：**固定信息区**（系统内置）+ **博客内容区**（超级管理员发布，2026-10-24 增补）。

**A. 固定信息区（不可编辑）**

- 「距离 XXXX 年考研还有 XXX 天」等信息展示。
- **考研硬节点时间线**（数据化，不写死；每年教育部公布后更新数据）：
  | 节点 | 大致时间 |
  |---|---|
  | 预报名 | 9 月底 |
  | 正式报名 | 10 月中 |
  | 网上确认 | 11 月初 |
  | 准考证下载 | 12 月初 |
  | 初试 | 12 月 |
  | 出分 | 次年 2 月 |
  | 国家线 | 3 月中 |
  | 复试 / 调剂 | 3–4 月 |

**B. 博客内容区（超级管理员发布，博客模式）**

- **内容来源**：由**超级管理员**撰写发布的文章（考研资讯、政策解读、备考建议、通知公告等），普通用户**只读**。
- **发布形态**（博客模式）：一篇文章 = 标题 + 正文 + 可选封面图；支持**草稿/发布**两态（草稿只有管理员可见，发布后对所有用户展示）。
- **展示**：信息模块内固定信息区下方为文章列表（倒序按发布时间），点击进文章详情页阅读。
- **管理**：超级管理员拥有文章的增删改查与发布/下线能力；**管理界面 = PC 管理后台**（§11，2026-10-24 定——博客是内容生产场景，需专门 PC 界面），手机端与 PC 用户端只读浏览。
- **谁是超级管理员**：`t_user.role` 字段标记（0=普通用户，1=超级管理员）；第一个管理员由部署者在库中指定，之后由管理员在 PC 后台**提拔/取消**（§11）。

> 设计意图：信息模块的固定部分满足"人人需要的考研日历"，博客部分让运营者/管理员能持续产出内容（类似公众号/博客），是模块里唯一的内容运营位。

### 5.2 复习模块（底部中）—— 自由库

- 对**所有** note 和错题的**自由浏览与复习**，**按科目分类**。
- **不提供艾宾浩斯复习队列**（队列只在主界面 Review 卡，§3/§6）。
- 用户可主动翻阅、筛选、修改已记录的 note/错题内容。

### 5.3 进度模块（底部右）—— 统计页

界面结构（2026-10-25 改版，参照不背单词统计页重做；**原逐日列表删除**，用户嫌臃肿）：

1. **概览 2×2 大数字**：今日学习&复习（记录条数）/ 累计学习（条数）/ 今日时长 / 累计时长。
2. **签到日历**：本周 MON~SUN 周条（签到 = 主题色实心圆，今天 = 「今」），右上**连续签到 N 天**。
3. **学习贡献墙**：GitHub 贡献图样式，26 周 × 7 天热力格（按当日学习时长 0~4 级），悬停看日期+时长；原学习总结页的贡献墙**迁入此处**。
4. **各科累计耗时**：紧凑条形，各科一栏。

- **各科目耗时为精确统计**（2026-10-24）：一次 Learn 只学一门科目（§4.1），`SUM(时长) GROUP BY 科目` 即真实耗时，不再走"多科目均分"估算。

## 6. 艾宾浩斯复习机制（★ 定稿）

### 6.1 复习间隔

**标准节奏：1 / 2 / 4 / 7 / 15 / 22 天，共六轮。**（2026-10-23 用户拍板）

- 用户在学习总结中输入的**所有 note / 错题**，自动全部进入艾宾浩斯复习队列。
- 今天记录的内容，分别在 **1 天后、2 天后、4 天后、7 天后、15 天后、22 天后** 应复习。
- 到期项出现在主界面「今日应复习」Review 卡（**队列唯一入口**）。
- 点 Review 卡进入**全屏沉浸式复习流程**（复盘用户自己记录的错题和结论，按科目组织）。
- **复习过程无自判环节**（2026-10-23 修订：取消原「模糊 / 已掌握」两键判定）。完成全部到期项的沉浸式复习后**直接回到主界面**。
- **每完成一次复习自动推进一轮**（round + 1，下一轮到期日照节奏顺延）；**六轮全部完成后出队**（仅留复习模块自由库可查）。
- **v1 节奏写死，不开放用户自定义间隔**。
- Review 卡显示当日到期数（跨科目堆叠计数）。

> 说明：此前讨论中出现过的 1/2/4/9/18 天为随手举例的错误数字，已废弃；以本节数字为唯一准绳。

### 6.2 与复习模块的边界

| | 主界面 Review 卡 | 底部中间复习模块 |
|---|---|---|
| 艾宾浩斯队列 | ✅ 唯一入口 | ❌ 无队列 |
| 内容 | 今日到期项 | 全部 note/错题自由库 |
| 形式 | 全屏沉浸式复习 | 按科目自由浏览 |

## 10. 技术栈与部署（已拍板）

**Spring Boot 3.x + Vue3 + MySQL + MinIO + Docker**，四容器 compose（MinIO 为 2026-10-23 增补）：

| 容器 | 职责 |
|---|---|
| Nginx | 托管 Vue 静态页 + 反代 `/api` + TLS 终结 |
| Spring Boot | REST API + 登录鉴权 + 图片压缩中转 |
| MySQL | 结构化数据持久化（文字内容、统计、复习状态），数据卷 `./data/mysql` |
| MinIO | **二进制对象存储**（图片等），私有桶 `exam-timeline`，数据卷 `./data/minio` |

### 图片存取链路（MinIO）

- **上传**：前端 → Spring Boot（multipart）→ 服务端压缩（缩放/转 webp 或 jpeg）→ 写 MinIO（object key 形如 `user_{id}/entry_{id}/{uuid}.webp`）→ MySQL 只存元数据（`t_entry_image`：object_key、content_type、size 等）。
- **读取**：私有桶 + 后端签发**预签名 URL**（presigned GET，短时效），前端拿 URL 直接渲染；不走后端流量中转。
- **文字内容一律存 MySQL**（可检索、可统计），MinIO 只管二进制。
- 需要图片直传优化时再升级为预签名 PUT 直传，v1 不做。

- **VPS**：建议 **≥ 2G 内存**（MySQL ~400MB + JVM ~300–500MB + MinIO ~100MB）。
- **备份**：`mysqldump` 每日 cron 定时备份 + MinIO 数据卷同步（`mc mirror` 或磁盘快照）。
- **HTTPS（裸 IP 访问，如 `https://122.22.222.1`）**：
  - 首选：**Let's Encrypt IP 证书**（2026-01-15 GA）——但**仅 6 天短期证书**（shortlived，160 小时），必须 **Certbot ≥ 5.4 全自动续期**（http-01 / tls-alpn-01），续期不能断。
  - 备选：免费域名 + 90 天常规证书。
- **备案**：国内 VPS 纯 IP 通常可行但不保证；中国香港 VPS 无备案限制。
- 图片：手机相册/拍照、电脑上传，服务端压缩后入 MinIO。

## 11. 客户端矩阵与管理后台（2026-10-24 定）

**博客发布是内容生产场景（写长文/传封面/管草稿），手机端体验差，管理必须有 PC 界面；同时普通用户在 PC 上学习也是真实场景，故 PC 端要覆盖普通用户功能。** 架构为 **C 端（手机 + PC）+ B 端（PC 管理后台）**，共用同一个 Spring Boot 后端 API 与账号体系。

### 11.1 三个界面

| 界面 | 给谁用 | 形态 | 功能 |
|---|---|---|---|
| **手机端** | 普通用户 | 响应式移动布局（与 PC 用户端**同一套代码**）+ Capacitor 壳 APK | 主界面 / Learn / Review / 进度 / 信息模块（博客只读浏览） |
| **PC 用户端** | 普通用户 | PC 网页（桌面布局） | **与手机端同功能**；布局桌面化重排；Learn 计时在 PC 上直接全屏展示（无需横屏引导） |
| **PC 管理后台** | 超级管理员 | 独立 PC 界面（入口如 `/admin`） | 文章管理（CRUD/封面/发布/下线）、用户管理（查用户、**提拔/取消超级管理员**） |

### 11.2 权限模型（叠加原则，2026-10-24）

- **超级管理员 = 普通用户的全部权限 + 管理权限**——角色是**叠加**不是互斥；管理员在手机端 / PC 用户端照常学习、记录、复习，只是 PC 上多一个管理后台可进。
- **注册永远只产普通用户**（role=0）；**种子管理员**由部署者在库中直接指定（`UPDATE t_user SET role=1`），之后的管理员均由管理后台的提拔接口产生（指定 id/邮箱 → role=1；可取消）。
- **权限卡口在应用层**：管理接口统一校验 role，普通用户请求被拒；数据库不做独立权限管理。
- 登录复用邮箱 + 密码，**一个账号走遍三界面**。

### 11.3 实现与部署

- 前端实现建议（2026-10-25 修订）：**管理后台与普通用户端分为两个 Vue 工程**（用户明确选择分开）；普通用户端一份**响应式代码三用**（PC 网页 / 手机浏览器 / Capacitor 壳 APK 内加载线上 URL）。上线走 Nginx 下载页分发 APK，不进应用商店。
- 部署影响：Nginx 托管三个入口（PC 用户端 / PC 管理后台 / APK 下载页），仍为四容器 compose（§10）。
